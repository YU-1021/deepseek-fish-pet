# 排查报错

## 步骤

1. **先读完整报错**，找出最关键的那一行——通常是最后一个 `Error:` / `Caused by:` / `fatal:`
2. 判断属于哪一类：语法 / 配置 / 依赖 / 权限 / 网络 / 逻辑
3. 先问清楚"之前能用吗、最近改过什么"。信息不够就先要上下文，别瞎猜
4. 给**最小验证**：一条命令、或一处很小的改动，让他先确认方向对不对
5. 方向确认了，再给完整的修法

## 注意

- 不要一上来就大改。先给「最可能的原因 + 一步验证」
- 不确定就直说「可能是 X，先试这个」，别硬编一个听起来很确定的答案
- 如果报错里已经有明确线索（缺文件、权限被拒、连不上），直接说结论，不用绕

## 常见对应

| 报错特征 | 多半是 |
|---|---|
| `ENOENT` / `no such file` | 路径写错、文件没生成、工作目录不对 |
| `EACCES` / `拒绝访问` | 权限、文件被别的程序占着、文件只读 |
| `ECONNREFUSED` / 超时 | 服务没起、端口不对、网络/代理 |
| `Cannot find module` | 依赖没装、路径大小写、装错目录 |
