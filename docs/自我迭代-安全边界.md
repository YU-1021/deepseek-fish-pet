# 自我迭代与学习能力 —— 安全边界（v0.1）

> 目标：以后做「自我迭代 + 增强学习」时，只让桌宠改**数据**，不改**程序**和**信任根**。
> 约定已拍板：**能改的文件加后缀 `.agent.md` / `.agent.json`**；没后缀的文件一律视为只读（AI 能读、不能写）。
> 本文是权威清单；实现时按文中的 INV 编号写测试断言。

## 1. 三层划分

| 层 | 内容 | 谁能改 | 保证手段 |
|---|---|---|---|
| **不可变内核** | 代码、依赖、协议、密钥、权限/审批地基、自我修改机制本身、评估与审计 | 只有人（代码走 PR，配置走设置页/人工） | 只读目录 + 无写接口 + 内置规则锁 + 审计 |
| **受控策略** | 能力开关、危险等级、阈值（CUA 权限档、hooks 模式/超时、automation 上限等） | 只有人，AI 只能「建议」 | 没有 `config.update` 类方法；改配置要人工 |
| **可学习数据** | 人格（外圈）、工作区记忆、技能候选、偏好画像、提案、交接笔记 | AI 可自改 | `.agent.*` 后缀 + 版本/锁/回滚 + 审批门 + 审计 + 灰度 |

## 2. 文件命名约定（INV-1）

**能改的加后缀；没后缀 = AI 只读。** 后缀统一放在扩展名之前：`SOUL.agent.md`、`preferences.agent.json`。

| 文件 | 角色 | 谁能改 |
|---|---|---|
| `apps/petd/**`、`apps/pet-ui/**`、`packages/**`、lockfile、构建/启动配置 | 代码与运行时 | 只有人 |
| `home/config.json`、`home/secrets.json`、`home/token.json` | 信任根 | 只有人 |
| `home/state/*.json`（情绪/提醒/自动化/审批门/静默活动/插件状态） | 服务自己写 | 服务进程（不算 AI 学习产物，不加后缀） |
| `home/SOUL.md` | 人格内核（身份/世界观等底座） | 只有人 |
| `home/SOUL.agent.md` | 可自演化的人格外圈（口头禅、相处细节、说话方式） | AI（版本/锁/回滚照旧） |
| `home/workspace/**` | 记忆正文（数据区，本身是 Git 仓库） | AI（现有 memory 工具规则不变；这里文件名不强制后缀） |
| `home/learning/*.agent.json` | 偏好画像、行为参数等学习产物 | AI 写候选，策略层读取 |
| `home/proposals/*.agent.md` | 自我迭代提案（改 prompt/技能/参数的理由 + diff） | AI 写，人审 |
| `home/skills/staging/*.agent.md` | 学习产出的候选技能 | AI 写，人审后转正 |
| `home/skills/*/SKILL.md`、`home/plugins/*` | 正式技能与插件（对外能力） | 人（UI/文件）；AI 只能读、只能写 staging/提案 |

合并规则：加载器只把 `*.agent.*` 当「动态数据」合并进运行时；代码目录里出现同名文件也不会被加载（INV-2）。

## 3. 不可变清单（INV 编号）

- **INV-3 信任根**：`secrets.json` / `token.json` / `config.json` 的权限地基（`hooks.enabled`、`hooks.mode`、`hooks.approvalEnabled`、`hooks.approvalTimeoutMs`、9 条内置规则、`cua.enabled/control/permission/skipTerminalAsk`、暂停权）只能人改；AI 不能放宽，只能建议。
- **INV-4 工具与协议**：工具定义、方法注册表、协议帧、错误码、网关认证/幂等/超时语义、系统提示词里的安全段，由代码生成，不能从 AI 可写的文件读取。
- **INV-5 自我修改机制**：提案生成→审批→灰度→回滚这套逻辑本身不可自举修改。
- **INV-6 评估与审计**：测试集、评分器、审计日志（`petd.log`）、验收指标只读/只追加；AI 不能写评测数据、不能改自己的评分；自己报告成功不算成功，要看真实回执（工具 ok、审批通过率、用户后续行为）。
- **INV-7 写盘白名单**：AI 通过任何工具/方法写盘，路径必须在 `home/` 的数据区，且命中「记忆区」或「带 `.agent.` 后缀的允许目录」；否则 `E_FORBIDDEN`。
- **INV-8 CUA 自我保护**：前台是 petd/编辑器/终端且操作目标指向自身代码/配置目录时强制人工确认并警告；终端输入保持逐次确认。
- **INV-9 审计**：所有 `.agent.*` 文件的变更带 `actor=agent` + 理由 + 前后 diff，可按文件批量回滚。
- **INV-10 禁止自我提权**：AI 不能给自己新增工具、权限、豁免名单、审批规则或环境变量；只能走「提案 → 人批」。

## 4. 学习能力怎么接（数据化策略）

1. **数据采集**：聊天 thumbs、审批的允许/拒绝（拒绝即负反馈）、任务成功/失败、用户纠正。
2. **离线评估**：固定且 AI 不可见的回归集 + 成本/延迟指标（INV-6）。
3. **候选产物**：prompt 片段、技能（staging）、检索权重、行为参数 → `learning/*.agent.json`、`skills/staging/*.agent.md`、`proposals/*.agent.md`，带理由与 diff。
4. **闸门**：高风险或改变边界的必须人批；低风险可自动灰度（如 10% 流量、3 天回滚窗口）。
5. **回滚**：每个候选有版本号，一键退回，回滚动作本身进审计。

红线（与 INV 对应）：不自我提权（INV-10）；不用 CUA 改自身（INV-8）；不改审批/评估器（INV-3/6）；学习数据里的文本一律当数据、不当 system 指令。
