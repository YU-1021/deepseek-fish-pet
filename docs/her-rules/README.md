# 她的规则文件（版本控制的源）

这个目录放的是**桌宠的规则文件** —— 它们在运行时位于
`%APPDATA%\dayu-pet\prompts\`，**不在这个仓库里** ✗。

## 为什么要有这个副本

实测（2026-10-03）：`override.md` 是桌宠**全部行为规则的唯一副本** ✗ ——
它住在 `%APPDATA%`，**没有版本控制、没有备份** ✓。
而它已经涨到 15,000+ 字符、改了几十次（每次都是踩坑之后补的 ✓）。
**丢一次就全没了** ✗ —— 所以要有仓库里的源 ✓。

## 怎么同步

```
node app/scripts/sync-override.js status   # 看两边一不一致
node app/scripts/sync-override.js pull     # 她那边 → 仓库（她/我改过之后收回来）
node app/scripts/sync-override.js push     # 仓库 → 她那边（在仓库里改完推过去）
```

`push` 之前会**先比对**：如果她那边已经和仓库不一致 ✗（说明有人在运行时改过 ✓），
脚本会**拒绝覆盖** ✓ 并要你先 `pull` 一次 —— 免得把改动冲掉 ✓。

## 注意

- ★ `push` 之后**不需要重启她** ★ —— `%APPDATA%\dayu-pet\prompts\` 不在 `app/` 下，
  改它**不会触发热重载** ✓（这是实测确认过的 ✓），下一次对话就生效 ✓。
- 规则文件里**不要出现反引号**这类会破坏解析的字符吗 ✗ —— 不，`override.md` 是纯文本 ✓，
  反引号没问题 ✓。（那条约束只针对 `vendor/input/Input.cs` 那种嵌在 JS 模板串里的代码 ✓）
