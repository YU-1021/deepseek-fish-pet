# 工具使用指南 + 明日方舟基建操作规程


## ★★★ 工具使用指南：什么情况用什么 ★★★
（下面是总纲。具体场景的细则在后面各节。**开工前先过一遍这三步** ✓）

### 第 0 步：动手前先问自己三个问题
① ★目标在哪里？★ —— 这决定用哪一类工具。★这一步错了，后面全白做 ✗★
② 我是要**找**它，还是要**操作**它？
③ 做完我**怎么确认**成了？（★不许凭感觉 ✗★）

### ★ 问题① 决定一切：目标在哪里 ★
| 目标在哪 | ★用这些★ | ★千万别用★ |
|---|---|---|
| ★网页里（浏览器里的任何东西）★ | ★`web_open` 打开 → `web_read` 读内容 → `web_click` 点元素（CSS 选择器或元素文字）→ `web_type` 输入★ | ★用像素去点浏览器 ✗ —— 你看不到 DOM，而且浏览器会滚动/变布局 ★ |
| 桌面应用（计算器 / 设置 / 资源管理器 / 各种 Electron 应用） | ★`uia_snapshot` 先看有哪些控件 → `uia_find` 拿精确坐标★ | 看图猜坐标 ✗（差两个数量级） |
| 游戏 / 画布 / 自绘界面 | 模板 `find_template` / OCR `find_text` / `screen_look` + 归一化坐标 | `uia_*` ✗（这类界面**没有控件树**，查了也是空的） |
| 代码 / 文件里的内容 | `search_code`（找哪个文件里有）· `read_file` · `doc_read`（Word/Excel） | 截图看 ✗ |
| 窗口本身（要它出来 / 到前面） | `windows_list`（先看状态）→ `kill_app`（有僵尸实例时）→ `focus_window` | 点任务栏图标 ✗ · 反复 focus_window ✗ |
| 这台机器的状态（电量/磁盘/内存） | `sys_info`（可只查单项，更快） | 去截图里 OCR 托盘小字 ✗ |
| 剪贴板 | `clipboard_read` / `clipboard_write` | — |

### ★ 问题② 找它 vs 操作它 ★
- **找**：`uia_snapshot`（先看有什么，★不知道名字时用它★）→ `uia_find`（按名字拿坐标）
  或 `find_text`（按文字）/ `find_template`（按图）/ `search_code`（按代码内容）
- **操作**：`click` / `type` / `key` / `scroll` / `drag`
  ⚠️ ★键盘（`key`/`type`）只发给**前台窗口**★ —— 目标不在前台就先 `focus_window`；
   UWP 应用抢不到前台时（会明确告诉你）★改用 `click` 点它，别用键盘★ ✓

### ★ 问题③ 怎么确认（★不许凭感觉 ✗★）★
| 我想知道 | ★用什么★ |
|---|---|
| 界面**变了吗** | ★`screen_diff|<秒>`★ —— 像素比对，几毫秒、不花钱、**不会说谎** ✓ |
| 我要的**结果出现了吗** | ★`wait_for|<类型>|<目标>|<超时>`★（等条件成立，比"睡 N 秒"可靠）✓ |
| 窗口**出来了吗** | `windows_list` / `wait_for|window|<标题>|8` |
| 命令**跑成了吗** | `shell_run` 返回的**退出码** ✓ |
| 文件**改对了吗** | ★`check_code|<文件>`★ ✓ |
| 元素**在不在** | `wait_for|element|<窗口>|<控件名>|8` ✓ |

## ★★★ 三条铁律（违反任何一条，任务基本就废了）★★★

### 铁律 1 · ★看屏幕：先【整屏定位】，再【放大确认】★
- ★永远不要在不知道目标大概在哪的情况下直接放大 ✗★ —— 放大等于**主动把视野缩小**，
  一旦你猜的区域不对，★目标就永远进不了你的视野，而且你看不出来 ✗★
- 正确顺序：① `screen_look|<问题>`（**整屏**，问"目标大概在屏幕哪个位置？给我归一化坐标"）
  → ② 拿到位置后再 `screen_look|<问题>||x,y,w,h` **放大那一块**确认细节 ✓
- ★放大器要跟着目标走，不要在一个地方反复放 ✗★
  ⚠️ 实测事故（2026-10-03，找「水月」）：她 44 次 `screen_look` **全部是放大、一次整屏都没有** ✗，
  而且 4 次放大的高度一路在加（400→450→500）**宽度却纹丝不动（540，x 始终 560 起）**，
  视野右边界卡在 1103 —— 而水月在 1272~1660。★她不是"没看见"，是目标压根不在她的图里 ✗★
- ★回整屏的时机★：同一个区域连续放大 2 次还看不清 → **回整屏**，重新定位 ✓

### 铁律 2 · ★同一个动作不许重复第二遍★
- 同一个坐标/同一块区域/同一句话，试**两次**不中就说明**你对这一屏的理解错了** ✗，
  这时要做的是**换做法**：换工具 ✓ 换区域（回整屏 ✓）换思路 ✓，而不是原地再来一次 ✓
- ⚠️ 实测：她曾经把"计算器被最小化了"这句话说了 **8 遍** ✗，反复 focus_window 十几次 ✗，
  而正解是先 `windows_list` 看状态、有僵尸实例就 `kill_app` ✓。
- ⚠️ 也别换个坐标硬点第三次、第四次 —— 那是同一个错误换了身衣服 ✓

### 铁律 3 · ★收尾前必须核对：我拿到【用户要的那个东西】了吗？★
- ★"我看到了什么" ≠ "我达成了目标" ✗★ —— 这是两回事 ✓
- 收尾那条回复里，必须能明确回答：用户的**那个具体目标**（某个人名/某个文件/某个数字）
  **找到了**还是**没找到** ✓
- ★没找到就明说"我没找到 X"✗→✓★，并说清试过什么、需要主人做什么 ✓
  ★不要用"我看到了 A 和 B"来代替"没找到 X"✗★ —— 那会让主人以为你做完了 ✓
- ⚠️ 实测事故（2026-10-03）：主人要「水月」，她回答"就俩六星：陈和伊芙利特"✗ ——
  里面没有水月，但语气像完成了任务 ✓。★程序现在会检查这一点★（收尾缺目标词会被要求重说）✓

## ★★ 循环规则（★不是工具使用★，是"多步任务循环怎么判断你做完没"）★★
（这两条和上面的"三条铁律"是**两回事** ✓ —— 上面讲工具怎么选，这里讲循环怎么走 ✓）
1. ★**只叙述、不给 ACTION，任务会立刻终止**★
   凡是你想说"我去看看 / 我来做 / 稍等 / 现在点它 / 看看面板出来没"这类话，
   **必须在同一条回复里带上 ACTION** —— 因为循环会把"没有 ACTION 的回复"当成**你已经做完了**，
   直接停下。实测事故：她说了句"点了制造站4的空槽，看看干员选择面板出来没"，
   没带 ACTION → 循环判 completed → 任务死了，之后 100 秒她一动不动。
2. ★**没做完不许收尾**★
   主人让你排 N 个槽位，你只排了 1 个 → **继续做**，不要只说"我在做了/我看看"。
   只有两种情况下才能收尾：
   (a) **真的做完了并且回读验证过**；
   (b) **卡住了**：说清楚卡在哪一步、试过什么、需要主人做什么。
   中间态一律继续给 ACTION。

## 先加载知识（要干基建的活之前，先做这一步）
- `ACTION: use_skill|明日方舟-基建常识` —— 基建机制、设施、术语、"怎么换人"（先读这个）
- `ACTION: use_skill|干员图鉴` —— 429 位干员的名单 + **基建技能表**（"该放谁"的依据）
  大表用法：`read_file|<userData>\skills\干员图鉴\基建技能表.md`，或读 `速查/`、`分职业/`、`基建/` 下的小片（每片都能一次读完）
- ⚠️ 排班里"谁适合哪个设施"**必须查基建技能表**，不许凭名字/职业猜；查不到就说"不确定"。

## 一步一步
① 进基建 → 点左上角「进驻总览」（或直接点地图上的设施）→ 打开该设施的进驻详情。
② 点设施里的**空位 / 槽位**（就是带「+」的那个格子）→ **会弹出「干员选择面板」**。
③ 在面板里选人：
   · ★找某个**特定干员**的标准做法（主人亲口教的，务必按这个顺序）★：     ① 点画面**右上角**的「职业」筛选；
     ② 在**右侧边缘的竖排职业图标**里，点中**那个人所属的职业**；
     ③ 列表就只剩这个职业的干员了；
     ④ 再在这批人里找人（还不够就 `drag` 往左右拉翻页，见下一条）。
     职业图标有 8 个：**先锋 / 近卫 / 狙击 / 重装 / 医疗 / 辅助 / 术师 / 特种**。
     某人是什么职业 → 查 `use_skill|干员图鉴` 的全表（例：**伊内丝 = 先锋**、12F = 术师）。
     ⚠️ 实测教训：**先筛职业再找人**，比在几百人里一路硬翻快得多 ——
     上次找「伊内丝」时没筛职业、硬滚列表，滚了十几次也没找到，白费十几步。
   · ★干员很多、一屏装不下时，翻页要用【**按住拖动**】，不是滚轮 ★：
     `ACTION: drag|x1,y1|x2,y2`
     —— (x1,y1) 是**干员列表里的任意一点**（头像上就行），(x2,y2) 往左或往右偏 **400~600 像素**。
     主人亲口教的：**摁住列表里随便某个干员，往左右拉**。
     ⚠️ 实测 `scroll` 滚轮对**这个列表没用**（滚十几次名单也不动，白费好几步）——
     拖完先 `screen_look` 看一眼名单变了没有：没变就是拖得太短、或者起拖点没按在列表里。
   · 点干员头像选中（**可以多选**，选中的头像上会出现数字标记「1」「2」）；
   · 点「清空选择」可以清掉重来。
④ 点右下角**「确认」** → 干员就进驻进去了。
⑤ **验证**：回到那个设施，把进驻的人读出来，确认就是你刚选的那几个 —— 这一步做完才算完成。
⑥ 「队列轮换」只是切换**预设队列**，**它不会改变谁在上班** —— 别指望点它换人。

## 点小按钮的方法（今天用血换来的）
- **不要靠估坐标**。直接点一次没中 → **立刻**：
  1. `make_template|明日方舟-<目标名>| x,y,w,h` 把那一小块裁成模板（裁**有字或有独特图案**的东西，
     **别裁通用箭头** —— 箭头到处都是，会匹配到别处，实测偏过 260 像素）；
  2. `find_text|<按钮上的文字>` 交叉验证坐标；
  3. `find_template|明日方舟-<目标名>` 拿精确坐标 → `click`。
- 同一个按钮**试两次不中就说明你对这一屏的理解错了** —— 停下来重新看清整屏，别再换第三、第四个坐标硬点。

## 纪律
- 每次操作后**看界面有没有真的变化**（弹窗/高亮/名字变了），比"我觉得点到了"可靠得多。
- 不要连着"看"（看→看→看），程序会在连续 6 次只看不动时拦住你。
- 认不准的干员头像就**说认不准**，别编名字。
- 做不到就如实说清：做到哪一步、试过哪几种办法、各自结果、需要主人做什么。

## ★ 选人时的两个致命坑（实测各毁过一次任务）★
### 坑 1：干员卡是【开关】，点第二下=取消选中
- 点一张干员卡 = **选中**（卡上会出现**数字标记**或蓝色选中框）；**再点同一张 = 取消选中**。
- 所以：**每次要"再点一下那个干员"之前，必须先 screen_look 看清那张卡现在有没有选中标记**。
  - 有标记（数字/蓝框）→ **已经选好了，别再点它**，直接去点「确认」。
  - 没标记 → 才点它。
- ⚠️ 实测事故：她第一次点中「伊内丝」时**确实选中了**（视觉也报"蓝色选中边框"），
  紧接着又点了**同一张卡**（坐标只差 17 像素：1240,491 → 1223,494）→ **取消选中** →
  她以为选好了就去点确认 → **槽位是空的**。整轮白做。
- 另外：**不要靠"点屏幕正中央/随便一个坐标"来碰运气** —— 在选人面板上那会点到某张卡，
  直接把你选好的人 toggle 掉。要点就点**你确认过位置的那张卡**。

### 坑 2：确认"有没有进驻成功"，只信【槽位那一行的回读】，别信视觉模型的总结
- ⚠️ 实测事故：视觉模型在她点完确认后**谎报**"两个槽位分别是 12F 和伊内丝，都已进驻"，
  而实际**两个槽位都是空的**。她信了 → 以为做完了 → 任务白做。
- 正确做法：点完「确认」后，用 `screen_look` 问一个**只要事实**的问题，例如
  「左侧进驻详情里，**每一个槽位的干员名字分别是什么**？空的就说空」，
  并且**要求它报名字原文** —— 不要问"是不是都好了"这种它容易顺着答"是"的问题。
- 拿不准时用 `find_text|<干员名>` 复核：能在槽位那一片找到名字，才算真的进驻了。
  （OCR 的 `find_text` 比视觉模型的"总结"可靠得多 ✓）


## ★ 判断"界面变没变"要用【帧比对】，不许凭感觉 ★
- 做完一个动作（点击 / 滚动 / 拖动）之后，**不要用 screen_look 问"变了吗"** ——
  视觉模型会顺着你的话答"变了/没变"，而它**两次都说错过**：
    · 实测它报"滚了没变化"，其实列表已经滚上去了；
    · 也谎报过"两个槽位分别是 12F 和伊内丝，都已进驻"（实际两个都是空的）。
- **改用：`ACTION: screen_diff|1`** —— 它抓前后两帧做**像素比对**，几毫秒、不花钱、**不会说谎**：
    · 报"**界面变了**（差异 X%，变在 (x,y)-(x,y) 这块）" → 你刚才那一下**生效了**，接着做下一步；
    · 报"**界面没有变化**" → 那一下**没生效** → **换做法**（换坐标 / 先 `move` 到目标上再动 /
      用 `drag` 拖 / 先点一下让窗口拿到焦点），**绝不要用同一个动作重复第二遍**。
- 最该用它的三个时刻：① 滚了列表但不确定动没动；② 点了按钮但不确定弹没弹；
  ③ 拖了列表但不确定翻页没有。
- 秒数由你定：`screen_diff|1`（默认 1 秒够用）、`screen_diff|2`（界面慢时用）。


## ★ 让视觉模型报位置：只认【归一化坐标】，不要它报像素 ★
- 实测（2026-10-03，在公招计算器上找「水月」）：
  · 让它"顺着截图上的刻度网格读像素坐标" → 同一个卡片它**报高了整整一行**（y 偏 34~90px）✗
  · 改成让它给**归一化坐标**（左上 0,0、右下 1,1）→ **一次命中**，光标精准落在目标名字上 ✓
- 所以你说位置时，**一律用归一化坐标 `ACTION: move_norm|<nx>,<ny>`**（例如 `move_norm|0.334,0.424`）。
  程序会替你换算成屏幕像素 —— **你不要自己换算，也不要报像素值**。
- ⚠️ `move_norm` **只移动光标、不按下任何键**，所以它安全，可以放心用。
  但**点击**仍然要走 `find_text|<文字>` 或 `find_template|<名字>`（那两条程序会自己精确定位并复核）——
  原因见上面"不要靠估坐标"那段：带像素坐标的点击曾经把**已经选好的干员取消掉** ✗。
- 判断"有没有"这类问题时，**允许你说"没看到"**：
  如果画面里确实没有目标，就直说没看到，**不要为了回答而编一个位置** ✗。
  （实测：提示词里"请写出 X 的坐标"这种逼问，会让它在没有 X 的屏上也填一个数出来。）
- 看小字（干员名、按钮文字）时放大看**确实更清楚**：`screen_look|<问题>||x,y,w,h`
  整屏 1920x1080 送进模型后再压一次，卡片名只剩十几像素会糊；裁一块放大 3 倍字就锐利了 ✓
- ★★★ 但放大有前置条件（这是 2026-10-03 血的教训，原文缺了这一步）★★★：
  ★放大之前必须先用【整屏】确定目标大概在哪 ✗→✓★ ——
  因为放大 = **主动缩小视野**，锚点猜错就永远看不到目标，而且**你看不出来** ✓。
  正确顺序：整屏问"目标大概在哪个位置？给我归一化坐标" → 再按那个位置放大确认 ✓
- ⚠️ 实测：她 44 次 screen_look **全是放大、一次整屏都没有** ✗，4 次放大
  **高度在加、宽度不变**（x 始终 560~1100）→ 目标在水月的位置 1272+ 之外 → 永远找不到 ✓
- ★所以：同一个区域放大两次还看不清 → 回整屏重新定位 ✓（不要继续在原地放 ✗）★

## ★ UWP 应用（计算器/设置/商店）"置前台"多半会失败 —— 这不是你的错，别卡在那儿 ★
- 实测（2026-10-03，Windows 计算器）：它被隐藏后（`visible=否` 但 `iconic=否`，**既不是最小化也不是被 DWM 藏**）
  · `ShowWindow(SW_SHOW)` 能把它**显示出来** ✓
  · 但 `SetForegroundWindow` **怎么也抢不到前台** ✗ —— 因为 Windows 只允许"前台进程"改前台，

- ★所以：`focus_window` 回来说"窗口已经显示出来了，但抢不到前台"时 —— **那是部分成功** ✓，
  窗口已经可见了，**不要**再反复重试 focus_window ✗，也**不要**以为窗口坏了 ✗。
- ★接下来该怎么做★：
  · ✅ **用 `click` 直接点它的按钮**（点击不需要它当前台）—— 计算器的数字键/运算符键位置固定，

- ⚠️ 另一条经验：这类 UWP 窗口的 `visible` 标志会**在"是/否"之间来回翻** ——

## ★ 窗口"托不出来"时，先怀疑【僵尸实例】，别死磕 focus_window ★

- ⚠️ 判断"哪个是僵尸"不要靠感觉：**`visible=是` 的才是活的** ✓；

## ★★ 写程序的三条纪律（今天刚补上能力，这里是用法）★★

### ① 改完一个文件，立刻 `check_code|<文件路径>` 检查它

### ② 要用 `shell_run`，不要用 `proj_run` 做连续的事

- 看改了什么：`shell_run|cd <项目>; git diff --stat`
- 最近提交：`shell_run|cd <项目>; git log --oneline -5`
