# 游戏助手（Aknight.gmaer）

给桌宠装一个「看得懂游戏、能替主人点」的手。能力来自**预习助手**（`C:\deepseek\预习助手`）里那套照 MAA 做的 MAA 抓帧 + PaddleOCR/模板识别 + 后台点击；petd 只做编排与安全闸门。

## 为什么分成两个进程

- 预习助手是独立项目，自带整套 MAA 运行库与资源副本（`models/maa/`，389MB（MAA v6.23.0）：`MaaCore.dll` + 依赖 DLL + PaddleOCR/PaddleCharOCR/任务/模板/ONNX），抓帧/识别/点击都不需要另装 MAA；它对外只暴露一个桥脚本 `tools/petd-bridge.js`。
- petd 用「一行 JSON 请求 / 一行 JSON 回复」的 stdio 桥调用它：不把 Python/ONNX 依赖塞进 petd，也不占常驻内存；每次调用 spawn 一次 node，用完即退（约 200–800ms）。
- 好处：识别算法/模型升级只改预习助手；petd 只依赖「op 契约」。
- 代价：每次调用有进程启动成本；未来可以改成常驻服务（预习助手已有 `service/percept_service.py` 常驻模式，可作下一步优化）。

## 数据流

```
聊天（Aknight.gmaer 插件）
  → 工具 game_look / game_find / game_click
    → petd 网关 game.*（方法）
      → GameAssistant（apps/petd/src/game/assistant.ts）
        → spawn node tools/petd-bridge.js（预习助手）
          → MAA method 8 抓帧（DXGI DesktopDup Window，1280×720）
          → PaddleOCR 识别 / 模板匹配（models/ 本地 ONNX）
          → 需要点击时 AsstAsyncClick 后台点击（不移动鼠标）
```

## 桥的 op 契约（预习助手 tools/petd-bridge.js）

| op | 作用 | 关键返回 |
| --- | --- | --- |
| `status` | 找游戏窗口 | `ok`、`game{title,proc,hwnd,w,h}` |
| `look` | 抓一帧 + OCR（可选 find/template） | `capture{w,h,path,blackRatio}`、`ocr{engine,text,lines,lineCount}`、`find[]` |
| `find` | 抓帧 + 找文字 | `found`、`coverage`、`box{...}` |
| `template` | 抓帧 + 模板匹配 | `matches[]`（分数/坐标） |
| `operators` | 干员头像/名字匹配 | `matches[]` |
| `click` | dry-run 返回计划；`allowReal:true` 才真点 | `dryRun`、`planned{x,y}`、`clicked` |

坐标一律是 **1280×720 抓帧坐标系**（游戏 1920×1080 下 1.5 倍）。

## 安全设计

1. **两层开关**：`config.game.allowClick`（默认 false）+ 调用参数 `real:true`。缺一不可，否则只返回计划。
2. **默认 dry-run**：`game.click` 不带 `real` 时绝不点击；插件 prompt 要求「先 dry-run 看计划，主人同意才 real」。
3. **一步一动作**：点完必须 `game_look` 看变化，没变就换做法，避免原地重复点。
4. **花资源必须问**：花理智/源石/合成玉/凭证前必须主人明确同意（插件 prompt 与 5 个技能反复强调）。
5. **不碰充值/删数据/改游戏文件**；不确定界面先看屏，不凭记忆点。
6. 失败/超时都返回中文错误（`E_UNAVAILABLE`/`E_INTERNAL`/`E_FORBIDDEN`），不会静默吞掉。

## 遮挡限制（重要）

MAA method 8 抓的是「桌面副本裁到窗口矩形」——游戏被浏览器/别的窗口**完全挡住**时，会拍到挡住它的窗口（实测抓到过 Bilibili 网页）。

- 桥的 `look` 返回 `capture.blackRatio` 与 OCR 文字；如果文字不像游戏 UI，说明被遮挡。
- 正确顺序：`cua_windows` 找到「明日方舟」窗口 → `cua_focus` 切前台 → 再 `game_look`。
- 部分遮挡（只挡一角）仍可能拍到游戏本体，但会漏掉被挡区域。

## 配置

```json
"game": {
  "enabled": true,
  "assistantDir": "C:\\deepseek\\预习助手",
  "nodePath": "",
  "timeoutMs": 30000,
  "allowClick": false,
  "gameHint": "明日方舟"
}
```

- `enabled`：总开关；关掉后 `game.*` 返回 `E_UNAVAILABLE`，聊天里也没有 `game_*` 工具。
- `assistantDir`：留空自动在 `C:\deepseek\预习助手`、`F:\DSH\大肥鱼\预习助手` 里找（要求存在 `tools/petd-bridge.js`）。
- `nodePath`：留空用 petd 自己的 node。
- `allowClick`：真点总开关，**建议一直关**，只在明确要让它动手时开。
- `gameHint`：找游戏窗口用的标题/进程提示（默认「明日方舟」）。

## 聊天工具（Aknight.gmaer 插件用）

| 工具 | 作用 |
| --- | --- |
| `game_look` | 看屏：画面尺寸、识别文字、可选 find 找字坐标 |
| `game_find` | 找字：覆盖率 + 中心坐标（点按钮前先定位） |
| `game_click` | 点击：默认 dry-run；`real:true` + 允许才真点 |

`game_click` 计入「每轮最多 3 次写操作」配额，防止模型乱点。

## 实测（2026-11-22）

- 离线识别回归（预习助手 `tools/verify-recognition.js`）：12/12；「剩余可放置角色:」0.9998 @(1081,551)，字符级 46/50 0.9999。
- 单帧 OCR 494ms、字符 ROI 169ms（PaddleOCR，本机 CPU）。
- petd 端到端（`scripts/game-smoke.mjs --live`）：18/18；真抓帧 1280×720、OCR 5 行、find 返回覆盖率；默认冒烟 14/14（不碰游戏）。
- 真机游戏画面 OCR 实测：「4/2| c38 剩余可放置角色:4 囚 39.0」。
- 单测 431/431（含 game 服务 8、网关 7、工具 3）。

## 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `E_UNAVAILABLE 游戏助手没开启` | `config.game.enabled=false`；改成 true 后重启 petd |
| `E_UNAVAILABLE 找不到预习助手目录` | `assistantDir` 不对或 `tools/petd-bridge.js` 不存在 |
| `E_INTERNAL 游戏助手调用超时` | 抓帧慢/游戏卡；调大 `game.timeoutMs` |
| OCR 全是网页内容 | 游戏被挡住；`cua_focus` 切前台再 `game_look` |
| `game.click` 返回 dryRun 但没点 | `allowClick=false` 或没传 `real:true`；两个都满足才真点 |
| 点了没反应 | 坐标是 1280×720 抓帧坐标；先用 `game_find` 核对坐标 |
