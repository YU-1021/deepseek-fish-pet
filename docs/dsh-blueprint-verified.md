# DSH 重构蓝图的【核实记录】

> 由我（会话里的 agent）在收到子智能体的蓝图 `docs/dsh-blueprint.md` 之后逐条核对。
> 原则：**别只信报告**（今天反复吃亏的一条）。

## 一、核对了什么

### 1. 蓝图说"`main.js:1318/1322/1333` 把工具失败当 user 消息回灌，是上下文污染的根因"
**核实结果：行号不准确** ✗。
- 那三行属于 `archiveSkills()` —— **技能归档**的子循环（`for (let i = 0; i < 8 && budget > 0; i++)`）。
- 那里的 `messages` 是**函数内局部数组**，**不会进会话**（`memory.session`）。
- 所以它不是"上下文污染的根因"。

### 2. 那真正的会话注入点在哪？（我自己 grep 出来的）
只有两处：
- `app/main.js:1522` — `memory.session.push({ role: 'user', content: '[系统] 我刚执行了操作 ' + a.tool + '…结果如下：\n' + cut })`
- `app/main.js:1646` — 另一处 `memory.session.push({...})`

**而"失败叙述污染"的真正机理**是：工具回执里的失败文本（如「❌ 坐标格式应为 x,y」「⚠️ 原地打转」）
混在 `content` 里、以 **user** 身份进了会话，随后被**压缩摘要**读进去、再回灌给她。

### 3. 但这一条**今天已经在更上游治过了** ✓
`app/src/memory/jobs.js` 的 `summarize()` 提示词已改成"**只记事实、明文禁止写她的心理活动/自我评价/
道歉/'我做不到'这类叙述**"。所以蓝图里 C2 的**边际收益比它估计的小**。

## 二、蓝图里仍然成立、且是真缺口的部分

| 蓝图条目 | 核实 | 桌宠现状 |
|---|---|---|
| C1 turn/step + 日志为唯一真相 | **部分成立**：`main.js` 里确有硬编码步数上限，但它不是主对话循环 | 主循环在 `renderer/chat.js` 的 `runTask`（递归 + `depth > stepBudget`）→ 确实该抽 `loop.js` |
| C3 重复调用检测：工具名+规范化参数、阈值 `[3,5,8]`、只提醒不阻止、真用户消息即重置、未登记工具透明 | **成立** | 我们的是 `slice(0,160)` 指纹 + 白名单 + 40 条滑窗 → **更粗**，值得换 |
| **C4 大输出 spill 到文件 + 头尾保留 + 精确省略字节数** | **成立** | 我们只有 `READ_CAPS` 硬截断（`main.js:1514`）+ watch 时间线写文件（只在一处）→ **该抽成通用模块** |
| C5 剪枝靠追加替代事件、绝不改写历史（`surface` 投影） | **成立**，但**工作量大** | 我们的 `tokens.clip()` 是就地截断 → 要改成投影层 |
| C6 工具自带 `timeoutMs`、只通知不抢跑 | **成立** | 各调用点各写 timeout（`asr/assistant/focuswin/input/llm/matcher`…）→ 该统一 |
| C7 「改前必读」用事件 + CAS 版本 | **成立** | 我们只有 `projects.safePath` 的越界检查 → 没有 observed 表 |
| C8 会话格式版本 + 相邻迁移链 | **成立** | `session.json` **没有版本号** → 该加 |
| B 不抄 cordis，只抄纪律（两层 + dispose + 三档钩子） | **成立** | `bus.js` 已经是 15 行 EventEmitter → 加到 ~120 行即可 |
| D 该放弃的（DI 反射/typert RPC/Zstd/compaction-basic/图片卸载/子agent配额） | **同意** | — |

## 三、结论

蓝图**方向正确、原则可抄**，但**引用行号需要复核**（已在本文件记录）。
实施优先级我建议调整为：**C4(spill) → C3(重复检测) → C6(超时) → C8(会话版本) → C1(loop 抽出) → C7 → C5**，
理由是：前四项都是**小改动、能独立测试、收益立刻可见**；C1/C5 动的是主循环与上下文投影，风险大、要在前面几项稳定后做。
